# 3-minute demo video script (target 2:50)

Record at 1080p. Use the live demo link, logged in with the "Try demo" buttons. Keep the browser zoom at about 110%. Fill the [brackets] with your own story: speak from real experience, do not read this word for word.

**0:00 - 0:25 | Hook and problem (face or voice-over on the landing page)**
"I'm [name], a medical student in [city]. On the wards, I learned history-taking by practising on real patients, with very little feedback. And I watched patients arrive with no structured history, sometimes with an emergency sitting in the same queue as everyone else. [One real moment from your experience, 1-2 sentences.] ClerkifyDx is my attempt to fix both sides, built on Meta's Muse Spark."

**0:25 - 1:15 | Student simulation (log in: Try as student)**
- Pick a case, e.g. "Child with fever". Say: "The AI patient stays in character and only gives history when I ask."
- Ask 3 questions live (duration of fever, convulsions, mosquito net). Switch language to Nigerian Pidgin for one question.
- Submit a short clerking and show the feedback: strengths, what you missed and why it matters, red flags.
- "Everything is stored in my learning history, so I can see which questions I keep forgetting."

**1:15 - 1:40 | Visual case (only if you added the images)**
- Open the chest X-ray case. Type your reading. Show Muse Spark's vision feedback.
- "Muse Spark looks at the actual image and critiques my reading against hidden reference findings."
- If the images are not added, skip this block and use the time for the intake section.

**1:40 - 2:20 | Patient intake and red-flag safety (log out, Patient intake without account)**
- Give consent, start intake, chat normally for 2 messages.
- Type a red-flag message (e.g. chest pain and difficulty breathing). Show the instant emergency guidance.
- Say: "This check is rule-based and runs before the AI. Emergency guidance never depends on a model or the network. The AI never diagnoses."

**2:20 - 2:45 | Doctor consult (Try as patient, then Try as doctor)**
- Patient generates the summary and requests the verified doctor.
- Doctor accepts, and only then sees the summary. Show the honest statuses, then send one chat message each way (chat opens only after acceptance).
- "Nothing says a doctor reviewed a case before they actually did."

**2:45 - 3:00 | Impact and what's next**
"Today this is a prototype: 11 text cases, English and Pidgin, 4 roles. Next: real-time chat for accepted consultations, a clinically reviewed case library, voice intake in local languages. The code is open source at github.com/Eman2123/ClerkifyDx. Thank you."

## Checklist before recording
- [ ] Live backend is warm (open the URL once; free tiers sleep).
- [ ] `MODEL_API_KEY` set on the server, no "Demo mode" banner visible.
- [ ] Dry-run every click once; keep each answer short so the AI replies fit the time.
- [ ] Do not claim anything that is not built (no real-time chat, no diagnosis).
- [ ] Final video is at most 3:00 and is public/unlisted with the link working.
